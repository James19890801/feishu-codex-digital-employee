# 阿充数字人：实时 30 条会话上下文、阿里黑话与全面回归设计

日期：2026-08-03  
状态：已完成对话确认，待书面复核  
适用仓库：`/Users/fengzhouchong.fzc/Documents/AIPR0S数字人`

## 1. 问题与目标

当前通用回复链路只读取 SQLite 中当前进程保存的 12 条摘要，并按发送者分隔。它不是钉钉当前会话的真实最近 30 条消息，也无法稳定包含阿充本人发出的历史回复。因此，模型可能遗漏正在讨论的话题、误判对方最后一句，或模仿错误的表达风格。

本次增量实现三个目标：

1. 每次生成普通对话回复前，实时读取当前钉钉单聊或群聊最新 30 条真实消息。
2. 以对方最后一句为当前回应目标，并只从阿充本人在同一会话中的历史回复提炼表达风格。
3. 建立可扩充、可消歧的阿里业务黑话语义层；在人员、同学、晋升、招聘、层级等语境下，将裸数字 `5`、`6`、`7`、`8`、`9` 优先理解为 `P5`、`P6`、`P7`、`P8`、`P9`。

原《阿充 AI 产品经理数字人：Prompt、记忆、知识与需求闭环设计》中的身份、隐私、1A、代码取证和通知规则继续有效。本设计只增加会话理解、企业语义和回归验收能力，不放宽任何权限。

## 2. 明确约束

1. “最新 30 条”指当前会话内按创建时间排序后的最后 30 条有效消息，包含双方消息；不跨联系人、不跨群、不跨线程拼接。
2. 当前待回复消息必须在上下文中出现且只能出现一次。
3. 回复目标是当前会话中时间最新的对方有效消息；系统消息、撤回提示、文件占位和纯机器人回声不作为目标。
4. 风格样本只选阿充本人发送的文本。其他人的口吻只能用于理解关系和语境，不能被当成阿充风格。
5. 历史读取失败、返回结构不完整或无法确认会话身份时，不调用模型生成事实性回复；返回简短降级说明并让可靠队列重试。
6. 原始 30 条消息只在单次回复内使用。SQLite 仅保存必要的去重、状态、审计和失败摘要，不新增跨会话原文语料库。
7. 群聊上下文仅包含当前群；回复仍只在明确 `@阿充` 的入站事件上触发。
8. 黑话识别依赖上下文，不把所有裸数字强制转换为职级。金额、日期、数量、版本号、时长和工作项编号保持原义。
9. 运行时仍为本机 Codex CLI；钉钉继续使用现有 DWS event-stream 链路，不切换悟空轮询、不使用悟空内置二进制、不新增第二条消息通道。

## 3. 方案选择

### 3.1 不采用：仅扩大本地摘要缓存

把 12 条改为 30 条实现简单，但进程重启、漏收阿充出站消息或 DWS 游标异常后仍会得到过期上下文，不能满足“每次拉最新 30 条”的要求。

### 3.2 采用：回复前按会话实时读取

每个入站消息进入串行会话队列并获得处理租约后，按会话类型调用 DWS：

- 单聊：`dws chat message list --open-dingtalk-id <对方> --time <当前消息时间后一秒> --direction older --limit 30 --format json`
- 群聊：`dws chat message list --group <openConversationId> --time <当前消息时间后一秒> --direction older --limit 30 --format json`

继续使用仓库当前配置的 `/Users/fengzhouchong.fzc/.npm-global/bin/dws`、profile 和 channel。该原链路 DWS 当前已验证版本为 `v1.0.55`，认证有效，两种查询形式均由本机命令帮助明确支持。查询结果经过规范化、排序、过滤和截断后进入 Prompt。

### 3.3 不采用：建立全企业聊天归档

全量归档会扩大隐私面、存储成本和权限风险，也不是正确回复当前对话所必需。

## 4. 模块边界

### 4.1 `conversation-context.mjs`

负责纯函数处理，不执行外部命令：

- 构造 DWS 最近消息查询参数。
- 解析 DWS 单聊和群聊返回结构。
- 统一消息字段：`messageId`、`conversationId`、`senderId`、`senderName`、`direction`、`content`、`createdAt`。
- 去重、过滤无效消息、按时间升序排列并截取最后 30 条。
- 确认当前待回复消息和对方最后一句。
- 提取最多 8 条阿充本人风格样本；优先使用最近、完整、非模板化的回复。
- 生成有明确说话人标签的 Prompt 片段。

### 4.2 `conversation-context-client.mjs`

负责受控执行：

- 只允许执行固定的 `dws chat message list` 命令族。
- 单聊只使用事件中可信的 `senderOpenDingTalkId`；群聊只使用事件中可信的 `openConversationId`。
- 使用当前已配置的 DWS 二进制、profile/channel 环境和超时限制。
- 要求 JSON 成功结构；输出截断、认证失败、超时或结构异常都返回带类型的错误。
- 写入读取成功时间、消息数、耗时和失败类型审计；不写入消息正文。

### 4.3 `alibaba-language.mjs`

负责确定性语义提示：

- 内置首批词条：职级数字、同学、拿结果、闭环、抓手、颗粒度、横向、纵向、owner、对焦、共识、体感、链路、沉淀、复盘、卡点、倒排。
- 每个词条包含标准含义、触发上下文、反例和必要时的追问条件。
- `5`–`9` 仅在同学、人员、HC、招聘、晋升、绩效、汇报线、管理、职级等上下文中映射为 `P5`–`P9`。
- 日期、金额、数量、版本、时长、ID 等上下文禁止职级映射。
- 模块只生成语义注释，不修改用户原文，避免损坏工作项 ID 或数据。

### 4.4 `index.mjs` 集成

普通模型回复前执行：

```text
可信入站事件
→ 当前会话串行化
→ 实时读取最近 30 条
→ 验证当前消息与最后一句
→ 提取阿充风格样本
→ 生成阿里语义注释
→ 组装身份、Bible、隐私、历史、语义和当前指令
→ Codex 生成
→ 回复长度与身份检查
→ 幂等发送
```

1A 需求写入、状态通知、操作员命令等确定性分支继续优先于普通模型回复，但涉及自然语言理解的需求澄清也应复用同一会话上下文；不得因为历史读取而重复创建工作项。

## 5. Prompt 合同

Prompt 中新增两个独立区块：

```text
当前钉钉会话最近 30 条真实消息：
[时间][对方/阿充/群成员名] 内容

当前回应目标：
[对方] 最后一句原文

阿充在本会话中的表达风格样本：
[阿充] 历史回复

阿里语境注释：
- “6”在本句人员层级语境下表示 P6，不是数量 6。
```

模型规则：

1. 先回答“当前回应目标”，历史只用于消歧，不能回到已结束的话题。
2. 风格模仿限于长度、直接程度、称呼、语气和结构，不复制隐私信息、承诺或历史事实。
3. 没有阿充样本时使用 Persona 默认风格，不伪造样本。
4. 语义注释为辅助信息；若与明确事实冲突，以消息原文和实时系统数据为准。
5. 不在用户可见回复里解释“我读取了 30 条”“我在模仿风格”等内部过程。

## 6. 失败、重试与隐私

| 场景 | 行为 |
|---|---|
| DWS 未认证或 token 失效 | 本轮失败，记录认证错误，进入既有有界重试；不调用模型 |
| 会话历史接口超时 | 本轮失败并重试；达到最终次数后发送一次简短失败通知 |
| 当前消息不在返回的 30 条内 | 将可信入站消息补入尾部并去重，同时记录 `current_message_appended` |
| 返回超过 30 条 | 排序后只保留最后 30 条 |
| 重复消息或分页重叠 | 按 `openMessageId` 去重；缺失 ID 时按发送者、时间和内容摘要去重 |
| 群聊出现其他成员隐私 | 仅用于当前群回复，不进入长期记忆，不向群外输出 |
| 没有阿充历史回复 | 使用 Persona 默认风格，风格样本区标明“无” |
| 裸数字语义不明确 | 保持原文；如果该语义决定答案，进行最短追问 |
| 消息发送结果不确定 | 保持既有 fail-closed 规则，不自动重复发送 |

## 7. 全面回归策略

验收不是单个测试命令，而是分层证据矩阵。每发现一项失败，先定位根因、修复并重跑对应层，再重新运行全量门禁。

### 7.1 纯函数与边缘场景

- 0、1、29、30、31、100 条历史输入。
- 时间乱序、重复 ID、相同内容不同消息、缺失发送者、缺失时间、空文本、撤回和媒体占位。
- 单聊双方消息与群聊多成员消息的说话人标记。
- 当前消息已存在、缺失和重复三种情况。
- 阿充没有样本、只有一条、超过八条、包含模板通知或敏感内容。
- `5`–`9` 在职级、日期、金额、人数、版本、时长、需求 ID 等语境下的正反例。
- 中英文混写：`P7`、`p7`、`7级`、`7 个`、`V7`。

### 7.2 受控 DWS 合同

- 单聊使用 `--open-dingtalk-id`，群聊使用 `--group`，两者互斥。
- 固定 `--direction older --limit 30 --format json -y`。
- 使用现有 DWS `v1.0.55`、event-stream、profile 和 channel；测试必须证明没有调用悟空轮询或悟空内置二进制。
- 认证失败、非 JSON、`success=false`、超时、超大输出和空结果。
- profile/channel 环境继承正确，用户文本无法注入额外参数。

### 7.3 回复与隐私集成

- 每一次普通回复调用前恰好读取一次当前会话历史。
- Prompt 包含最后一句、正确角色、最多 30 条和最多 8 条风格样本。
- 不跨单聊、群聊或发送者泄漏历史。
- 历史失败时 Codex runner 调用次数为 0。
- 重试不会产生第二条外发消息；出站回声不会触发回复。
- 自聊、普通单聊、群聊明确 `@`、群聊未 `@`、阿充本人群内消息均符合既有策略。

### 7.4 现有业务链路回归

- 身份、Persona、Bible、隐私边界和排除范围。
- 本地 Codex runtime 选择、超时、流式/缓冲输出和错误恢复。
- 1A 两个需求池的查询、产品分流、代码读取、创建/更新回读、订阅和状态通知。
- 消息持久化、租约恢复、限流、死信、幂等发送和数据库迁移。
- 钉钉 DWS event-stream、自聊读取、发送回执和联系人精确解析；确认悟空轮询未启用。
- 看板状态、Maintenance 条件、A1 卡片、日志和健康检查。
- 服务停止、启动、重启后的游标、处理中消息恢复和重复回复防护。

### 7.5 真实环境验收

1. 运行静态检查和全部 Node 测试，要求退出码为 0。
2. 运行本地 Codex runtime smoke，确认选中 `codex`。
3. 通过 DWS 对受控测试会话读取真实最近 30 条，核对数量、顺序和双方消息。
4. 发送包含阿里职级黑话的受控消息，核对回复是否按真实上下文理解并符合阿充风格。
5. 对 WebAgent 与 AI 协同空间运行只读 1A 和代码仓库探针，不创建测试垃圾需求。
6. 重启主服务和看板，运行健康检查并在浏览器确认不存在 `Maintenance required`。
7. 所有门禁通过后，向谢冰雪精确发送一次指定私人消息并保存回执。

## 9. 完成标准

1. 普通回复前真实读取当前会话最新 30 条，不再依赖 12 条进程内摘要作为主上下文。
2. 回应目标始终是对方最后一句有效消息。
3. 只模仿阿充本人在当前会话中的表达风格。
4. 阿里职级数字与普通数字通过上下文正确消歧。
5. 历史读取失败时不生成假上下文回复，也不泄漏其他会话内容。
6. 新增测试、全部现有测试、静态检查、运行时、DWS、1A、浏览器和重启验收全部通过。
7. 回归报告逐项记录首次失败、修复和重测结果。
8. 谢冰雪只收到一次指定消息，并取得确定的钉钉发送回执。
