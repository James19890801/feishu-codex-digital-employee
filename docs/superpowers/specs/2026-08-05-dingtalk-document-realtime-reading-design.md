# AIPR0S 钉钉文档实时读取设计

## 目标

修复 AIPR0S 在钉钉对话中收到钉钉文档授权卡或链接后，错误进入飞书文档检索并回复“资料暂时打不开”的问题。阿里巴巴部署的实时知识读取只使用数字人平台配置的 DWS 身份、Profile 和 Channel，通过钉钉文档接口检索与读取正文。

## 已确认授权边界

- 账号本人可以按标题或关键词搜索当前账号可访问的钉钉文档，并基于正文回答。
- 任何用户在当前会话的当前消息中明确提供钉钉文档链接时，数字人可以使用账号本人的 DWS 权限读取该链接，并仅在当前会话中基于正文回答。
- 上述授权不等于允许非本人按关键词遍历账号全部文档。非本人未提供明确文档链接时，只能读取知识目录中已通过 `readerIds` 明确授权的文档。
- 当前消息里的文档正文只作为本轮回答上下文；不得因为一次分享自动进入公开知识库、扩大读者范围或写回原文档。
- 现有身份、群聊、人工接管、敏感信息和高风险动作边界保持不变。本功能只读，不执行文档修改、权限变更或对外转发。

## 选择的方案

采用独立的钉钉文档知识适配器，并在实时消息入口按通道选择适配器。

相比直接在 `src/index.mjs` 中继续增加条件分支，独立适配器可以把链接识别、DWS 参数、搜索结果解析、正文读取、权限判断和错误分类放在可单测的边界内。相比让 Codex 在回复阶段自行决定是否调用 DWS，确定性适配器可以保证真实文档内容在生成回答前已成功读取，失败时也不会编造。

钉钉消息不得回退到飞书文档搜索。飞书通道的兼容代码可以保留，但只允许由飞书通道显式调用。

## DWS 接口契约

运行时必须继承 `config.dingtalkBin`、`config.dingtalkProfile` 和命令级 `DWS_CHANNEL`，不得使用 PATH 中偶然命中的其他 DWS，也不得把 Channel 写入全局环境。

### 搜索

使用 DWS 1.0.56 当前推荐接口：

```text
dws drive search --query <query> --limit 8 --profile <profile> --format json --yes
```

文档结果从 `doc_results.documents` 读取；钉盘普通文件结果位于 `drive_results.items`，不作为在线钉钉文档正文读取候选。旧的 `doc search` 已弃用，不进入生产实现。

搜索结果按以下顺序筛选：

1. 规范化标题完全匹配；
2. 标题包含完整查询词；
3. DWS 相关性顺序中的前置结果。

单次最多读取三个候选，避免把大量无关文档送入模型。

### 读取

使用：

```text
dws doc read --node <node-id-or-url> --profile <profile> --format json --yes
```

DWS 原生接受 `https://alidocs.dingtalk.com/i/nodes/<nodeId>` URL 或 node ID。成功响应必须同时满足 `success=true`、存在 `nodeId`、存在标题且 `markdown` 非空；否则按未读取处理。

## 数据流

1. 钉钉事件流保留当前消息原文、发送者、会话和通道元数据。
2. 适配器从当前消息提取 `alidocs.dingtalk.com/i/nodes/<nodeId>` 链接并去重。
3. 若存在明确链接，直接逐一调用 `doc read`，不先执行搜索。
4. 若没有链接且发送者是账号本人，从知识请求中提取查询词并执行 `drive search`，再读取最多三个候选。
5. 若没有链接且发送者不是本人，只解析知识目录中对该发送者明确授权的 `dingtalk_doc` 条目；不执行账号级全文搜索。
6. 成功读取的 Markdown 按单文档和总上下文上限截断，附带标题与钉钉来源链接，作为可信业务资料注入回答提示。
7. 实时回答入口按 `metadata.channel` 或标准化 chat ID 选择钉钉适配器；钉钉路径不创建或调用飞书 Client。
8. 公共网页读取器跳过已由钉钉适配器识别的内部文档 URL，避免重复请求和误报网络失败。

## 失败处理与可观测性

- 链接格式不合法、搜索无结果、DWS 进程失败、业务权限拒绝、超时、返回结构异常和空正文必须区分记录。
- 错误日志和审计只保留经过截断、脱敏的错误摘要，不记录 Token、Channel、Profile 或文档正文。
- 明确链接读取失败时，回答应说明“钉钉文档读取失败”及可操作原因；不得再出现“飞书资料搜索暂时不可用”。
- 标题搜索无结果时说明未找到匹配的钉钉文档，并建议补充标题或直接发送链接。
- 多个文档中部分成功时使用成功项回答，并明确未读取项；全部失败时不把标题或摘要当成正文。
- 任何失败都不得自动改权限、重置认证、改用其他账号或绕过 DWS Channel。

## 测试与全面回归

实施严格采用红—绿—重构：每项生产行为先写失败测试并确认失败原因，再写最小实现。

### 自动化测试

1. 直接 node URL 和带查询参数 URL 能提取同一 node ID。
2. 非钉钉 URL、伪造 host、缺失 node ID 和重复链接不触发 DWS 读取。
3. 明确链接由任意发送者提供时可读取，并且不触发 `drive search`。
4. 本人无链接知识请求使用 `drive search --query`，正确解析 `doc_results.documents`。
5. 非本人无链接请求不执行账号级搜索；目录显式授权条目仍可读取。
6. 搜索结果优先精确标题，最多读取三个候选。
7. `doc read` 成功、空正文、部分失败、全部失败、非零退出、超时和畸形 JSON 均有确定结果。
8. 单文档和总上下文字符上限生效，来源标题和链接保留。
9. 钉钉实时入口不调用飞书知识搜索，飞书兼容入口不受破坏。
10. 用户看到的钉钉失败文案不再包含“飞书”。
11. 内部钉钉文档 URL 不进入公共网页读取器。
12. DWS 子进程始终使用配置的绝对二进制、Profile 和命令级 Channel。

### 真实链路验收

1. 使用数字人当前 `dingtalkBin`、Profile 和 Channel 执行认证状态检查。
2. 用《会话级文件直传接口》的真实分享 URL 执行 `doc read`，验证标题、node ID 和非空正文。
3. 用标题执行 `drive search`，验证 `doc_results.documents` 命中后再读取正文。
4. 使用捕获的同结构授权卡消息 fixture 跑实时编排，验证生成模型收到正文而非降级提示。
5. 运行聚焦测试、`npm test`、`npm run check`、`git diff --check`、隐私扫描和运行时健康检查。
6. 安装/重启本地数字人服务后读取健康状态，确认钉钉事件流与认证仍在线。

真实验收只记录命令状态、文档标题、node ID 和正文是否非空，不把文档正文、个人配置或授权数据写入 Git。
