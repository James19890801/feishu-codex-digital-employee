# 悟空钉钉单通道与阿充数字人身份设计

## 目标

将本机数字人的钉钉运行时永久切换为悟空 DWS 单通道，并将对外人格统一为“阿充的数字人”。保留 AIPRO 作为产品、控制台和授权系统的名称，但任何面向钉钉联系人的自我介绍、隐私转交和 AI 回复不得把数字人自称为 AIPRO。

## 范围和非目标

本次修改包含：

- 钉钉入站从 `dws event consume` 改为悟空 `chat message list-all` 增量轮询。
- 钉钉出站使用同一悟空 DWS 二进制的 `chat message send`。
- 对话人格、首次接管问候、隐私边界和主人转交文案统一为“阿充”。
- 控制台显示钉钉当前是悟空轮询通道，不再误报事件流已连接。
- 本地配置永久指向已登录的悟空 DWS 二进制。

本次不重命名 AIPRO 产品、安装包、许可证产品 ID 或控制台品牌。不保留原开放版 DWS 事件流作为自动备用通道，避免双通道重复消费和重复发送。

## 通道架构

配置增加显式的 `dingtalkTransport` 字段，本机使用 `wukong-polling`。运行时在该模式下不启动 `event consume` 子进程，只启动一个受控的轮询循环。

轮询器每次使用上次成功游标与当前时间构造有重叠的时间窗口，调用：

```text
dws chat message list-all --start <local-time> --end <local-time> --limit 50 --cursor <cursor> --format json
```

当 `hasMore=true` 时继续使用 `nextCursor` 翻页，直到完整覆盖当前窗口。只有所有分页成功后才推进持久化时间游标。现有 SQLite 入站消息表以 `openMessageId` 提供最终去重，重叠窗口不会触发重复回复。

## 入站选择与身份

悟空 `list-all` 返回会话组、`singleChat`、会话 ID 和消息发送人 `openDingTalkId`。归一化规则为：

- 单聊：接收非本人发送的新消息。
- 自聊：允许阿充给自己发的消息触发数字人，但继续使用现有出站回声标记与熔断器拦截数字人自己发出的内容。
- 群聊：仅接收内容中明确 `@阿充` 或 `@阿充James` 的消息，并排除阿充本人或数字人的出站回声。
- 非文本占位符按现有安全策略忽略，不将无法判断方向的文件或图片当作新请求。

运行时启动时通过配置的 `dingtalkOwnerOpenId` 识别阿充。本机配置写入已经由实名搜索和实际投递验证过的本人 `openDingTalkId`。

## 出站发送

悟空模式的发送器继续使用 `chat message send`：

- 单聊使用 `--open-dingtalk-id`;
- 群聊使用 `--group`;
- 每次发送传入稳定 `--uuid` 实现 24 小时幂等；
- 继续使用 `--yes --format json`;
- 不向悟空旧版 CLI 传入其不支持的 `--profile` 和 `--ai-tag=false`;
- 只接受 `success=true` 且包含 `openTaskId` 的明确成功回执，超时、无效 JSON 或缺少回执按模糊失败处理，不自动改走桌面发送。

## 对外人格与文案

对外人格的统一名称是“阿充的数字人”。首次接管问候固定为：

> 你好，我是阿充的数字人。阿充现在不在，我可以先协助处理公开或已授权的事项；需要他本人决定的内容，我会请他确认。要继续聊吗？

`PERSONA.md`、AI 运行时提示词、隐私边界和主人转交文案中，所有“詹老师”、“James 老师”和“AI 助理 AIPRO”的人格指代都改为“阿充”或“阿充的数字人”。代码中只与产品、许可证、安装包或日志标识相关的 AIPRO 名称保留。

## 状态、迁移与错误处理

控制台通道状态将 transport 显示为 `Wukong DWS polling`。连续成功读取一个完整时间窗口后，状态为已认证且已连接；轮询失败时保留最近错误并按有界退避重试。

现有开放版 DWS 造成的死信不自动重放，因为其 `openDingTalkId` 可能属于不同应用命名空间。迁移验收通过后，可以将这批历史死信标记为“传输迁移前失败”而不发送，但必须保留审计记录。

## 验证

自动化验证覆盖：

- 悟空 `list-all` 参数、分页和游标推进。
- 单聊、自聊、群聊 `@阿充`、非 @ 群消息和出站回声的归一化。
- 悟空发送参数不包含 `--profile` 和 `--ai-tag=false`。
- 对外问候、Persona 和隐私转交不含“詹老师”或“AI 助理 AIPRO”。
- 旧事件流模式的现有测试保留，但本机配置不再选用它。

真实验收必须同时满足：

1. LaunchAgent 重启后主进程稳定。
2. 控制台显示悟空轮询通道在线。
3. 向阿充自聊发送一条新的入站验证消息，由运行中的服务消费并回复。
4. 最终向阿充的钉钉发送更正后的身份消息，并通过会话回读拿到 `openMessageId`。
