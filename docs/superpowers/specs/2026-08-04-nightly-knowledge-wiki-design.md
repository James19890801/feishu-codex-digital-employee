# AIPR0S 每晚知识 Wiki 同步设计

## 目标

每天 18:00 将阿充真实账号上下文中的钉钉聊天、AI 听记、钉钉文档，以及本机 Codex 对话和工作产物增量整理为 AIPR0S 的私有知识库，并同步一份可见的钉钉 Wiki 日报。

## 关键约束

- 钉钉访问只允许使用独立 DWS Channel：`~/.npm-global/bin/dws`、指定 `--profile`，并在单次命令环境中注入 `DWS_CHANNEL`。禁止调用悟空 DWS。
- 原始资料默认只对 owner 可检索。聊天、纪要和 Codex 对话不能因为数字人在群里被 @ 就向其他人泄露。
- 任何来源读取失败必须标记为“未读取”，保留上次游标；只有成功响应才能推进游标。
- 运行产物和采集状态位于被 Git 忽略的 `data/knowledge-wiki/`，不得提交个人内容、token 或凭证。
- 同一日期重复运行必须幂等；并发运行由锁阻止，中断遗留的死进程锁必须自动恢复。

## 选择的架构

采用“确定性本地同步器 + Codex 定时心跳 + 钉钉 Wiki 镜像”的混合架构。

本地同步器负责低 token、可测试的采集、脱敏、去重、游标与 Markdown 构建；AIPR0S 在每次回答时动态检索本地 Wiki，无需重启。Codex 自动化任务每天 18:00 触发同步器并报告来源状态。钉钉侧使用专属知识库空间和按日生成文档；生成文档按内容哈希幂等覆盖，绝不覆盖用户已有文档。

纯提示词方案会反复读取全量内容且难以保证幂等；纯系统定时器无法承接 Codex 对话及可见的运行报告，因此不采用。

## 数据流

1. 读取 `state.json`，首次运行从 30 天前开始，之后从各来源成功游标继续。
2. 通过 DWS Channel 分页读取跨会话消息、AI 听记列表与详情、Drive 文档元数据及可读正文。
3. 增量解析 `~/.codex/sessions/**/*.jsonl` 中用户与助手可见消息，只收集上次修改时间之后的文件。
4. 扫描配置允许的工作目录中近期 Git 提交与 Markdown/文本产物；排除 `.git`、`node_modules`、`data`、凭证文件和隐藏目录。
5. 对内容执行凭证与敏感标识脱敏，以稳定来源 ID + 内容哈希去重。
6. 原子写入 `daily/YYYY-MM-DD.md`、`index.json` 和 `state.json`。
7. 若配置了钉钉 Wiki 空间，则查找/创建当日日报节点，并以精炼索引幂等更新系统自建文档。
8. AIPR0S 收到知识类问题时，仅 owner 可从本地索引检索；返回内容带来源定位。

## 失败与恢复

- 单一来源失败不阻断其他来源，日报列出该来源“未读取”和精简错误原因。
- 失败来源不更新成功时间和游标，次日自动重试。
- 本地写入使用临时文件替换；进程崩溃不会留下半份索引。
- 同步器返回非零只用于整体基础设施失败；来源级错误通过结构化状态报告。
- 分页有单次上限，未完成回补在后续运行继续，避免一次性消耗过多配额与 token。

## 验收标准

- DWS 子进程环境包含指定 Channel，且路径策略拒绝悟空 DWS。
- 成功空结果与读取失败在状态中可区分。
- 重复输入不会重复出现在当日日报或钉钉 Wiki。
- owner 能检索新增 Wiki 内容，其他发送者得不到私有结果。
- 每天 18:00 的自动化任务已启用，并能在本地工作区执行同步脚本。
