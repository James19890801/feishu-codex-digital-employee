# 微信公众号私聊静默策略设计

## 目标

微信个人号收到公众号推送或私信时，不进入普通私聊 AI 回复链路，也不向公众号私聊目标发送文字、图片或文件，从工程上避免机器人之间互相回复和无效 token 消耗。

现有“指定公众号文章自动阅读、评论并转发朋友圈”功能继续保留。该功能是明确配置的独立自动化，不属于公众号私聊回复。

## 识别边界

仅对微信渠道的点对点会话生效。GeWe 回调中的公众号原始账号 ID 采用 `gh_...` 形式；识别逻辑集中为纯函数，避免各调用点重复实现。

普通微信好友、微信群、Owner 自聊及其他渠道不受影响。

## 数据流

1. GeWe 回调标准化时识别公众号发送方，并在元数据中标记。
2. 消息仍可进入现有持久化入站队列，以维持统一的去重、可观测性和失败恢复语义。
3. `processIncoming` 解析消息后，优先执行现有的指定公众号文章观察逻辑。
4. 若文章自动化认领该消息，则按原有独立流程处理并结束。
5. 若消息来自公众号但未被文章自动化认领，则记录静默审计事件并立即结束；不写关系记忆、不解析附件、不调用普通 AI、不发送回复。

## 出站防线

统一微信发送层在任何网络请求前检查目标。若目标是点对点公众号账号，则拒绝文字、图片和文件发送，并返回稳定的错误码。这样即便未来出现新的入站旁路或主动发送调用，也不会实际向公众号私聊发消息。

上层普通文本发送入口同步执行静默抑制并写审计记录，避免将策略性拦截当作可重试故障。底层 GeWe 通道保留硬拒绝，覆盖绕过上层入口的调用。

## 可观测性与错误处理

- 入站静默记录 `wechat_official_account_private_message_ignored`，包含脱敏前既有的内部消息、会话和发送方标识字段，不记录新增正文内容。
- 上层出站抑制记录 `wechat_official_account_private_send_suppressed`。
- 底层硬拒绝使用稳定错误码 `WECHAT_OFFICIAL_ACCOUNT_PRIVATE_SEND_BLOCKED`，且必须发生在任何 `fetch` 调用之前。

## 测试

- 纯策略测试覆盖公众号 ID、普通微信 ID、群 ID 和跨渠道目标。
- GeWe 标准化测试验证公众号元数据标记。
- 入站处理策略测试验证未配置公众号被静默，指定公众号文章仍可被独立自动化认领。
- GeWe 发送测试验证文字、图片和文件均在网络调用前被拒绝。
- 既有微信好友和微信群测试保持通过。
