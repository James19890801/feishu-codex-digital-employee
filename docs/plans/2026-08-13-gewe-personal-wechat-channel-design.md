# GeWe 个人微信统一通道设计

日期：2026-08-13  
状态：已确认（方案 A）

## 目标

在现有 AIPRO 本地数字员工中正式启用个人微信通道。GeWe 仅负责接管个人微信账号以及收发消息；消息进入本机后，继续复用现有统一运行时、Codex、Persona、Bible、记忆、队列、限流、审计和回复策略。

个人微信不是一套新的数字人，也不建立微信专属提示词或业务规则。

## 已确认的响应规则

- 单聊：所有符合现有安全和响应策略的新消息进入统一处理链。
- 群聊：只有明确 @ 当前个人微信账号时才进入统一处理链。
- 真人优先：账号本人在某个会话中普通手动发言后，该会话暂停数字人自动回复 5 分钟。
- 顺延：暂停期间账号本人再次手动发言，从最新发言时刻重新计算 5 分钟。
- 控制口令：继续支持“暂停回复”“恢复回复”等现有人工控制口令。
- 规则复用：除此以外完全遵循现有通道的判断、回复、记忆和治理规则。

## 方案选择

采用方案 A：用已经接入主运行时的 GeWe REST + Webhook 适配器替代不可行的 macOS 微信界面自动化方案，并补齐真人接管识别、正式通道界面和部署配置。

未采用的方案：

- macOS 微信界面自动化 POC：依赖窗口、辅助功能权限和界面状态，正式退役，不再出现在运行路径、Dashboard 或 macOS 服务恢复列表中。
- 独立微信处理服务：会复制队列、记忆和响应逻辑，不符合“只新增一个通道”的目标。

## 架构

```text
微信联系人或微信群
        │
        ▼
GeWe 个人微信账号接管
        │ HTTPS Webhook
        ▼
GeWe Webhook Adapter
        │ 标准化消息
        ▼
现有统一持久化消息队列
        │
        ▼
现有触发规则 / 真人接管 / 记忆 / 限流 / 审计
        │
        ▼
本地 Codex 数字人运行时
        │ 回复文本
        ▼
GeWe postText
        │
        ▼
原个人微信会话
```

## 组件职责

### GeWe 通道

- 使用 GeWe API Token 和 App ID 检查账号在线状态。
- 注册带随机路径密钥的公网 HTTPS 回调。
- 将 GeWe v1/v2 文本回调标准化为统一入站消息。
- 通过 `postText` 将统一运行时的最终回复发送回原会话。
- 串行发送，并保持服务商要求的最小发送间隔。

### 统一运行时

- 继续负责入站去重、持久化、失败重试、死信、按会话串行处理和审计。
- 继续使用同一套 Persona、Bible、Codex 模型、对话历史及业务能力。
- 不为微信复制新的问答处理分支。

### 真人接管

GeWe 回调中的账号本人消息分为两类：

1. 数字人发送后的服务商回声：由现有 outbound echo 记录识别并丢弃，不能触发接管或二次回复。
2. 本人真实手动消息：作为已认证 owner activity 进入统一接管逻辑，更新对应会话的 `human_takeover` 状态并静默结束处理。

接管状态只作用于当前会话，不影响其他联系人、群聊或其他 IM 通道。接管期间收到的对方消息不回复，但继续写入上下文；超时后数字人根据后续新消息恢复响应，不追发暂停期间的旧消息。

## 数据流

### 普通单聊

1. GeWe 推送联系人消息。
2. 适配器验证事件并生成稳定消息 ID、微信会话 ID 和发送者 ID。
3. 统一队列去重并排队。
4. 统一运行时执行现有响应规则并调用本地 Codex。
5. 最终文本经 GeWe 发回同一联系人。

### 群聊

1. 适配器解析群 ID、群成员 ID 和 @ 信息。
2. 未明确 @ 当前账号的消息直接忽略，不进入回复队列。
3. 明确 @ 的消息进入与单聊相同的统一处理链。

### 本人手动接管

1. GeWe 推送账号本人发出的普通消息。
2. 若命中 outbound echo，则仅记录为已处理回声。
3. 否则标记为 `ownerActivity`，进入对应微信会话。
4. 统一接管机制将暂停时间更新为事件发生时间加 5 分钟，并保留该手动消息作为上下文。
5. 后续本人发言继续顺延；接管期内对方消息只记忆不回复。

## 配置与凭据

- `geweAppId`：GeWe 控制台中的稳定 App ID/设备 ID。
- `gewePublicCallbackBaseUrl`：转发至本机回调端口的稳定公网 HTTPS 地址。
- `geweCallbackPort`：当前数字人实例接收 GeWe Webhook 的本地回调端口；多实例部署通过不同端口完成路由隔离。
- `geweMentionNames`：用于 v2 回调无法提供精确 @ ID 时的显示名兜底。
- GeWe API Token 存入 macOS Keychain，不写入配置文件、浏览器持久化、日志、快照或 Git。
- 回调路径密钥单独随机生成并存入 Keychain。
- `geweEnabled` 仅在配置完整并通过连接验收后启用。

## 控制台

- GeWe 是 Dashboard 中唯一的“个人微信”通道，不再称为“旧版”。
- 删除 macOS UI 自动化的卡片、开关和控制 API；安装或升级主服务时主动卸载其历史 LaunchAgent，防止两套实现并行操作微信。
- 正式卡片展示：已安装、已配置、已认证、回调监听、回调注册、账号在线和最近错误。
- 配置保存继续使用现有流程：校验、Keychain、备份、重启、真实连接验收、失败回滚。

## 故障与安全边界

- GeWe 初始化、在线检查、回调或发送失败，只将个人微信标记为降级，不停止飞书、钉钉、企业微信或 Codex。
- 本地 Webhook 只监听 `127.0.0.1`，公网访问必须经 HTTPS 反向代理或隧道。
- 回调使用不可预测路径密钥、恒定时间路径比较、JSON 类型检查和请求体上限。
- 重复回调依靠 `appId + newMsgId` 去重。
- GeWe 是第三方个人微信服务，并非腾讯官方开放 API；界面和文档持续提示账号风控风险。

## 本期范围

- 正式支持 GeWe 已有的文本消息闭环。
- 图片、语音、文件等媒体只有在 GeWe 下载、内容解析和回传能力完整接入统一媒体管线后才视为支持；本期不做额外承诺。
- 不改变其他通道的现有响应规则。
- 历史 POC 源文件可暂时保留用于迁移审计，但任何产品运行路径都不得再加载、展示或启动它。

## 验收标准

1. 单聊联系人发送文本后，由现有本地数字人生成并原路回复。
2. 群聊普通消息不回复，明确 @ 当前账号时按现有规则回复。
3. 账号本人普通手动发言会静默触发当前会话 5 分钟接管。
4. 接管期间再次手动发言会顺延 5 分钟。
5. 接管期内对方消息保留到会话上下文但不自动回复。
6. 接管超时后，后续新消息恢复自动响应。
7. 数字人发送回声不会触发接管或形成回复循环。
8. 重复 Webhook 不会造成重复处理或重复回复。
9. GeWe 断线或凭据错误不会影响其他通道和本地 Codex。
10. Dashboard 能清楚配置和展示正式 GeWe 个人微信通道状态。
