# AIPRO 自包含 macOS 发行设计

## 目标

把现有 AIPRO 项目交付为可分享的 macOS 安装包。接收者无需安装 Node.js、拉取源码、执行脚本或配置 LaunchAgent；下载与安装后，打开 AIPRO 即可进入本地配置页。

首版同时支持 Apple Silicon 与 Intel Mac，分别产出 `AIPRO-mac-arm64.dmg` 和 `AIPRO-mac-x64.dmg`。免费发行版采用临时签名，不依赖 Apple Developer Program；因此用户首次打开时仍需在 macOS“隐私与安全性”中手动允许一次。

## 产品体验

1. 用户下载与本机芯片匹配的 DMG。
2. 用户把 AIPRO 拖入“应用程序”并打开。
3. 免费版首次按 macOS 要求完成一次“仍要打开”。
4. AIPRO 自动完成本地目录初始化、后台服务安装和启动。
5. AIPRO 打开内置控制台；若是全新安装，直接进入首次配置流程。
6. 配置流程先选择真人身份或机器人身份，再仅显示相应 IM 渠道与字段。
7. AIPRO 自动探测 Codex、Qoder、CodeBuddy 等可用的本地无界面运行时；用户无需填写路径。
8. 配置完成后，现有消息、队列、记忆、审计、授权和通道隔离链路照常工作。

## 架构

### 应用包

`AIPRO.app` 包含：

- 原生 Swift 启动器；
- 对应 CPU 架构的 Node.js 运行时；
- 生产依赖与项目运行文件；
- 仪表盘静态资源；
- 语音转写辅助程序；
- 启动、诊断和卸载所需的受控资源。

应用包内资源只读。所有可变内容放到 `~/Library/Application Support/AIPRO`，包括配置、Persona、Bible、知识目录、SQLite、日志、备份和运行状态。这样升级应用时不会覆盖用户数据。

### 启动器与后台服务

启动器不再假定源码仓库存在。首次启动时，它从应用包资源初始化支持目录，生成缺失的默认文件，并安装指向应用包内 Node 与入口文件的用户级 LaunchAgent。已有支持目录只补缺失文件，不覆盖配置或数据。

每次启动按以下顺序执行：

1. 校验应用资源与支持目录；
2. 安装或修复 LaunchAgent；
3. 启动本地仪表盘；
4. 探测 `127.0.0.1` 健康接口；
5. 成功后在应用窗口加载控制台；
6. 核心服务仅在配置与授权满足现有规则时启动。

启动器保留恢复服务能力，但不再强制跳出到默认浏览器。控制台作为应用主窗口，另提供“在浏览器中打开”菜单。

### 配置与身份

首次配置新增显式身份入口：

- 真人身份：显示飞书真人、钉钉真人和经明确授权的个人微信路径；
- 机器人身份：显示企业微信机器人等官方机器人路径；
- 两类身份可以同时启用，但每个通道继续保留独立生命周期和故障域。

该入口只组织现有配置能力，不改变通道实现、身份声明或安全边界。密钥继续写入 macOS Keychain，非敏感配置写入支持目录的 `config.local.json`。

### 本地运行时感知

复用并扩展现有 `discoverAiRuntimes`：

- 扫描 PATH、常见应用目录和已知 CLI 位置；
- 后台运行只接受具有稳定 headless 接口的运行时；
- 自动模式按现有优先级选择；
- 没有可用运行时时，控制台显示安装建议和重新扫描按钮，后台业务链路保持停用；
- 不要求用户编辑二进制路径。

## 核心链路保护

本次改造在发行、启动和首次配置层完成。以下模块不重写：

- IM 入站与出站实现；
- SQLite 队列、去重和顺序保证；
- 记忆、学习与审计；
- 授权、邀请和 Keychain 密钥边界；
- 通道隔离和真人/机器人身份声明；
- AI 运行时调用适配器。

运行路径通过兼容配置或环境变量注入支持目录，避免把现有代码改造成另一套系统。

## 错误处理

启动失败时不显示空白页，也不要求用户打开终端。启动器展示当前阶段、可读错误、重试、打开日志目录和修复后台服务入口。

主要错误分别处理：

- 应用资源缺失或损坏；
- 支持目录不可写；
- LaunchAgent 安装或启动失败；
- 固定端口被占用；
- 本地仪表盘超时；
- 未发现可用 AI 运行时；
- IM 尚未配置或凭据无效。

通道配置失败只降级对应通道，不阻塞其他通道和配置页。

## 打包与分发

构建脚本在干净暂存目录中安装生产依赖、复制允许清单中的运行文件、加入指定架构 Node、编译原生程序、临时签名整个应用包，并生成 DMG。构建过程不得复制 `config.local.json`、用户数据、日志、缓存、密钥或当前工作区的未跟踪内容。

以后获得 Apple Developer Program 账号时，只需为同一构建产物增加 Developer ID 签名、公证和 stapling，不改变应用架构与用户数据路径。

## 测试与验收

- 在 Apple Silicon 和 Intel 架构分别验证包内二进制架构；
- 在全新 macOS 用户目录进行首次启动测试；
- 验证无系统 Node、无源码仓库时仍能打开控制台；
- 验证已有数据升级时不覆盖配置、Persona、Bible 与 SQLite；
- 验证重复打开不会重复安装或产生多个后台进程；
- 验证可用运行时自动识别，无运行时时给出可操作提示；
- 验证真人与机器人身份选择只影响配置呈现，不改变现有安全边界；
- 运行现有单元、机制验收、Swift 类型检查和浏览器冒烟测试；
- 解包检查 DMG 不包含密钥、本地配置、日志和开发者私有数据。

验收终态：另一台没有 Node、没有源码的兼容 Mac 下载 DMG，完成系统首次放行后即可打开 AIPRO 配置页，并且无需终端部署动作。
