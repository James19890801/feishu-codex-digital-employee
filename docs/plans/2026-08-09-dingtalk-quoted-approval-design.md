# 钉钉群聊引用授权设计

## 目标

让高风险动作可以在钉钉群聊中由 Owner 以自然方式授权：Owner 使用钉钉原生“引用回复”功能引用数字员工发出的授权请求，并回复“同意”。该授权只作用于被引用的那一笔动作，不使用六位确认码。

## 已选方案

采用“引用消息 ID + Owner 身份”方案。

相较于孤立回复“同意”，引用关系可以在同一群存在多笔待授权事项时准确定位动作；相较于六位码，它不要求用户记忆或抄写额外信息。交互卡按钮可以作为未来增强，但不作为本次实现前提。

## 安全边界

一次有效授权必须同时满足：

1. 入站消息来自钉钉群聊。
2. 消息发送者的 `OpenDingTalkID` 与配置的 Owner ID 完全一致。
3. 正文规范化后恰好为“同意”。
4. 入站事件包含钉钉原生 `quoted_message.message_id`。
5. 被引用的消息 ID 对应数字员工真实发出的一笔待授权请求。
6. 待授权请求属于当前群聊，仍在有效期内，且状态为 `pending`。
7. 执行时重新校验 Owner 身份，并以幂等方式只执行一次。

以下情况一律拒绝：孤立的“同意”、复制授权文字但未原生引用、其他成员回复、跨群引用、引用未知消息、过期授权、已取消授权和重复授权。

## 数据流

1. 群成员提出可能导致 Multica 写入的请求。
2. 系统生成预览和待授权记录，记录原请求、目标群、动作快照、过期时间和状态。
3. 系统把授权请求发到原群并 @Owner；发送成功后提取钉钉返回的开放消息 ID，将它绑定到待授权记录。
4. Owner 原生引用该消息并回复“同意”。
5. 入站标准化层保留 `quoted_message` 的消息 ID、会话 ID和发送者 ID。
6. 授权处理器按被引用消息 ID 查找待授权记录，完成身份、会话、正文、状态和有效期校验。
7. 校验通过后原子消费授权，调用现有 Multica 预览快照校验和幂等执行机制。
8. 系统在原群发送成功、失败、已过期或已处理回执，并写入审计日志。

## 组件变更

### 钉钉入站标准化

`src/im-channels.mjs` 将 DWS 扁平事件中的可选 `quoted_message` 映射到内部消息元数据。只信任钉钉提供的开放消息 ID，不解析引用摘要文本。

### 待授权存储

新增独立的引用授权存储，以授权请求为中心，而不是复用当前按“类型 + 会话 + 请求人”索引的交互草稿。存储支持：

- 创建待授权记录；
- 绑定数字员工发出的钉钉消息 ID；
- 按引用消息 ID查询；
- 原子消费或拒绝重复消费；
- 过期清理。

本次只接入 Multica 高风险写入，避免把日历预约和个人待办的现有请求人确认语义无意扩大。

### Multica 授权流程

群聊中的写请求不再直接执行，也不把普通 Owner 群消息视为通用写权限。系统只允许生成待授权预览；真正写入必须经过引用授权处理器。现有 Owner self-chat 确认流程保持兼容。

## 错误处理

- Owner 发送孤立“同意”：提示引用对应授权请求。
- 非 Owner 引用回复“同意”：明确告知只有 Owner 可以授权，不执行。
- 引用未知、过期或已消费请求：告知授权无效，不执行。
- 发送授权请求后未取得开放消息 ID：不进入可授权状态，提示稍后重试。
- 外部写入结果不确定：沿用现有歧义结果保护，停止自动重试并要求人工核对。

## 审计

审计记录保存授权请求内部标识、授权请求消息 ID、原请求消息 ID、群聊 ID、审批人 ID、授权时间、执行结果和拒绝原因。对外回执不暴露内部数据库标识或凭据。

## 测试策略

- 钉钉事件标准化测试：正确保留引用消息 ID，普通消息不产生伪引用。
- 授权存储测试：绑定、查找、过期、原子消费和重复消费。
- 授权判定测试：Owner/非 Owner、同群/跨群、引用/孤立、同意/其他文本。
- Multica 集成测试：群聊写请求只生成授权预览，Owner 引用同意后执行一次。
- 回归测试：Owner self-chat 写入、普通群聊查询、待办和日历确认行为不变。
