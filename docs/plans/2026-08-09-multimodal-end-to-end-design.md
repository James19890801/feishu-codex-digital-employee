# AIPRO 飞书与钉钉多模态端到端设计

## 目标

在 AIPRO 指定工作区内打通两条完整链路：

1. 飞书或钉钉收到网页链接、文件、图片、语音或视频后，可靠下载、解析、理解并回复原会话。
2. AIPRO 生成或取得工作区内的 PDF、Office、HTML、图片、音频或视频后，按通道能力回传原群聊或私聊。

本轮优先完成飞书和钉钉。工作区内部不再使用“只有 Owner 私聊可以收文件”的旧限制；工作区外的任意本机文件仍禁止读取或发送。

## 方案选择

采用统一内容管道，而不是继续在 `src/index.mjs` 中叠加通道分支。

- 通道适配层只负责把平台事件转换为统一内容引用，以及下载或发送二进制内容。
- 内容解析层只根据 MIME、扩展名和实际文件特征处理网页、文档和媒体。
- AI 编排层只接收整理后的文本、图片和来源说明。
- 投递层根据通道能力选择原生媒体消息、文件附件或说明消息。

不采用外部文档转换服务。本轮优先使用本机能力，避免把群内材料发送到新的第三方服务。

## 内容模型

每条入站消息转换为一个内容信封：

```js
{
  messageId,
  channel,
  chatId,
  chatType,
  senderId,
  text,
  items: [{
    kind,          // web | image | document | audio | video | file
    source,        // url | feishu | dingtalk
    resourceId,
    fileName,
    mimeType,
    localPath,
    provenance,
  }],
}
```

解析结果统一包含可供模型使用的 `textBlocks`、`imagePaths`、`warnings` 和 `sources`。一个附件失败时保留其他附件的结果，不让整条消息失败。

## 入站链路

### 链接

链接读取先执行现有的 SSRF 防护，再按响应 MIME 路由：

- HTML、XHTML、纯文本、JSON：提取可读正文。
- PDF、Word、Excel、PPT、HTML 文件：下载到消息临时目录后交给文档解析器。
- 图片：下载后交给视觉模型。
- 音频和视频：下载后进入本地转写与关键帧处理。
- 不支持的二进制类型：保留来源和明确警告，不猜测内容。

重定向后的每一跳都重新验证地址。文件名优先使用 `Content-Disposition`，其次使用 URL 路径和 MIME 推断。

### 飞书

飞书消息中的图片、文件、音频和 `media` 都转换为内容引用。当前消息可以包含多个引用；文本后续指令仍可在同会话、同发送人、30 分钟内引用最近附件。

下载使用用户身份资源接口。视频同时下载媒体文件和封面（事件提供封面时）；没有封面时本地生成关键帧。

### 钉钉

钉钉图片、语音和视频继续通过 `mediaId` 与 `chat message download-media` 下载。

普通文件消息解析 `[文件] ... fileId: ...` 占位内容，使用 `dws drive download --node <fileId>` 下载。文件名从占位内容或下载结果提取。群历史轮询、实时事件和恢复轮询使用相同解析规则。

### 文档解析

支持：

- PDF：先抽取文字；文字不足时启用 macOS PDFKit + Vision OCR，保留页码边界。
- DOCX：段落和表格。
- DOC：使用系统转换工具转换为文本，失败时走 Quick Look/OCR 降级。
- XLSX/XLS：工作表名称、使用区域和单元格文本，限制总字符数。
- PPTX/PPT：页面文字和备注；旧格式失败时走 Quick Look/OCR 降级。
- TXT、Markdown、CSV、JSON、LOG、XML、HTML：按文本读取；HTML移除脚本和样式后提取可读内容。

每个附件保留文件名、格式、页码或工作表来源。总输入受字符、页数、体积和处理时间限制，截断必须显式告诉模型。

### 图片、语音和视频

- 图片直接作为本地图片输入交给支持视觉的 AI 运行时。
- 语音使用现有本地转写器，不调用新的外部转写 API。
- 视频抽取音轨转写，并等间隔生成最多四张关键帧；部分步骤失败时使用剩余信息继续回复。

## 出站链路

所有待发送文件必须经过真实路径校验，且位于 AIPRO 工作区或隔离产物目录内。允许回传原群聊和原私聊，不再限制为 Owner 私聊。

### 飞书

- 图片使用 `--image` 原生图片消息。
- 视频生成封面后使用 `--video` 与 `--video-cover` 原生视频消息。
- Opus/Ogg Opus 使用 `--audio`；其他音频作为文件附件。
- PDF、Office、HTML、ZIP 和其他文档使用 `--file`。
- 说明文字与附件分别发送，使用稳定幂等键并记录投递结果。

### 钉钉

DWS 无法把本地图片转换为内联 `mediaId`。因此本地图片、文档、音频和视频统一使用 `--msg-type file --file-path` 作为可下载附件发送，再发送一条说明消息。若内容引用本身已有有效 `mediaId`，才允许使用内联图片模式。

### HTML

HTML源文件可以直接作为文件发送。请求“可预览”时，同时生成 PDF 或 PNG 预览；预览生成失败不阻断 HTML 源文件投递。

## 错误处理与可靠性

- 每个内容项独立记录 `downloaded`、`parsed`、`analyzed`、`delivered` 或失败原因。
- 下载、解析和投递使用有界超时、大小限制和重试；永久格式错误不重试。
- 临时目录按消息隔离，并在处理结束清理。
- 幂等键由消息、附件和目标通道共同生成，避免重试造成重复文件。
- 文件投递也进入现有出站语义查重和回声防护体系，但文件摘要与文本摘要分别计算。
- 审计日志只记录文件名、格式、大小、哈希片段和状态，不记录文件正文。

## 测试与验收

自动化测试遵循测试先行：

- URL MIME 路由、重定向复验、文件名解析和私网拒绝。
- 飞书 `image/file/audio/media` 多附件归一化与下载参数。
- 钉钉 `mediaId` 和 `fileId` 占位解析、下载参数与失败降级。
- PDF、扫描 PDF、DOCX、XLSX、PPTX、HTML 提取。
- 飞书原生图片/视频/音频/文件发送参数。
- 钉钉文件附件和说明消息发送参数。
- 工作区包含校验、符号链接逃逸、体积限制、超时、幂等和局部失败。
- 完整现有测试与机制验收不得回归。

真实通道冒烟使用指定测试群，发送明确标注的测试材料并验证：入站解析、AI回复、文件回传、重复保护、失败提示和临时文件清理。真实发送前先内部核对目标群和测试内容。

## 完成定义

飞书和钉钉对上述链接与附件类型均存在自动化契约测试；两条通道各完成一轮真实测试群入站和出站冒烟；完整测试、静态检查和健康检查给出新鲜证据；未通过的能力不得标记完成。
