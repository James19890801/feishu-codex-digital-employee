# 微信跨会话专业口径与高成本任务审批设计

## 目标

1. 同一联系人提出同一专业问题时，群聊与私聊共享同一套专业结论、证据顺序和工程框架；渠道只影响称呼、篇幅和发送形式。
2. 图片/视频生成、长篇报告和文件型交付在真正消耗模型或启动 Multica 前，必须由詹老师在经过验证的个人微信私聊中批准。
3. 审批消息必须清楚回答四件事：谁、在哪里、想做什么、请求什么决定。

## 事实与根因

- 生产库现有 1,139 条微信助理回复，其中群聊 501 条、私聊 638 条；群聊平均 133 字，私聊平均 219 字。
- 对话历史按 `chat_id` 隔离，因此同一联系人在不同会话里会得到不同历史。
- 关系记忆为了隐私采用非对称召回：私聊可使用该联系人公开群聊经历，群聊不可使用其私聊经历。这个边界必须保留，但关系记忆不能改变专业结论。
- 空 @ 快路径、普通模型回答、人工授权补发没有共用一个专业答复契约。
- 当前普通报告请求可直接进入模型；显式 PDF/PPT/Word 等交付还存在 Multica 创建旁路，没有统一经过 Owner 成本审批。

## 专业答复一致性

新增一个渠道无关的专业答复契约：

- 输入只包含当前规范化问题、可公开引用的材料、Persona/Bible 版本和证据规则。
- 关系记忆拆成“表达偏好”和“事实上下文”。表达偏好只能影响语气；私聊事实不得进入可复用的专业核心答复。
- 对当前问题去除 @、引用包装和纯传输文本后生成请求指纹。相同联系人、相同请求指纹优先复用已成功生成的专业核心答复。
- 群聊/私聊渲染只允许调整称呼、@、篇幅和附件发送，不允许改变结论、证据优先级或风险判断。
- 审计记录请求指纹、答复契约版本、来源范围和是否复用，便于以后直接比较。

## 高成本任务定义

一律需要审批：

- 生成或编辑图片、海报、头像、视频、动画。
- 生成 PDF、PPT/PPTX、Word/DOCX、Excel/XLSX、HTML 等交付文件。
- 明确要求白皮书、深度调研、完整/全面/系统性/长篇报告。
- 启动 Multica、专家团或其他后台执行来完成上述交付。

不需要审批：

- 读取、识别、评论或分析用户已经发来的图片、视频、报告。
- 普通问答、短分析、摘要、提纲、几段文字建议。
- 查询已有任务进度或下载已经批准生成的成品。

詹老师在经过验证的个人微信私聊中直接提出高成本任务，视为对该任务的直接批准。其他任何人、群聊或渠道提出时都必须先暂停。

## 审批消息

标准格式：

```text
詹老师，微信用户「{昵称}」（微信 ID：{ID}）在{位置}想让我做：

{具体交付物和要求}

这属于{成本类别}，会消耗较多模型资源。请求您的同意。

请引用这条消息回复“同意”或“不同意”；如需修改，请回复“改成：……”。
```

位置优先使用真实群名，例如 `微信群「AI流程与组织变革交流一群」`；私聊写 `与我的微信单聊`。无法解析群名时回退为 `微信群（ID：...）`。昵称和微信 ID 同时展示，防止重名串单。

## 审批状态机

`pending_notify → awaiting_owner → approved|rejected|expired|ambiguous → executing → executed|execution_failed`

- 审批与来源消息 ID、请求指纹、原会话和具体交付绑定。
- 同一个来源消息只能创建一条审批，通知、回复和恢复执行均使用幂等键。
- 只有经过验证的 Owner 私聊回复有效；群内“James 同意了”或伪造昵称无效。
- 批准后从持久化任务快照恢复原任务，并把结果发送回原会话。
- 拒绝或超时只通知原请求人，不执行任务。
- 模糊回复不猜，要求詹老师引用原审批明确回答。

## 入口与防绕过

成本门应放在消息规范化、Owner 身份校验之后，所有实际执行路由之前，并覆盖：

- 普通 `runCodex` 长报告生成。
- 显式文件交付与 `handleMulticaArtifactFollowup`。
- Multica Issue 创建、派队和重新执行。
- 未来接入的图片/视频生成工具。

提示词中的成本规则只作为第二道防线，不能替代确定性代码门。

## 验收

- 非 Owner 在群聊或私聊请求图片、视频、长报告或文件交付时，不启动模型重任务或 Multica，只向詹老师发一条结构完整的审批消息。
- 审批消息包含准确昵称、微信 ID、群名/单聊位置和具体交付物。
- 詹老师批准后只执行一次，并回到原会话交付；拒绝、超时、重复回调均不会执行。
- 普通图片阅读、短答和摘要不被误拦截。
- 同一联系人、同一规范化专业问题跨群聊/私聊的核心结论一致，且不泄露私聊内容。
