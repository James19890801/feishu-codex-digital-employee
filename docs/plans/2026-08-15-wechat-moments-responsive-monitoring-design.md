# 微信朋友圈及时响应设计

## 结论

GeWe 当前回调结构没有列出朋友圈发布、评论或点赞事件，不能依赖 webhook 做严格实时监听。采用“5 分钟轮询 + 微信消息入站助推扫描”的组合，兼顾响应速度、接口负载和可靠性。

## 机制

- 朋友圈 worker 启动时扫描一次，之后每 5 分钟扫描最近 50 条。
- 任意个人微信 webhook 消息入站时调用 `nudge()`；若距离上次扫描不足 60 秒则忽略。
- 同一时刻只允许一轮扫描执行；扫描进行中收到的多个助推请求合并，避免队列堆积。
- 普通私聊和群聊消息仍由 webhook 入站队列立即处理，不等待朋友圈扫描。
- 朋友圈新评论继续优先于点赞和主动评论；所有写操作沿用持久化幂等键。

## 验收

- 单元测试覆盖 5 分钟默认值、入站助推、60 秒冷却和并发合并。
- 机制验收覆盖 GeWe webhook 与朋友圈 worker 的连接。
- 上线后通过审计记录确认启动扫描完成、服务在线且无重复写入。
