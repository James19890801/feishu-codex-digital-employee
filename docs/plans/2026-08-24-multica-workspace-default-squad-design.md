# Multica 空间级默认承接小队设计

## 目标

当数字人从任意渠道把新需求创建到「北京AI流程管理特训营」空间时，自动交给该空间内的「詹老师的搞事小团队」承接，不再要求用户选择执行小队。

## 方案选择

考虑过三种方案：

1. 在业务代码中直接写死北京空间和小队 ID。实现快，但难以维护和迁移。
2. 当空间只有一个小队时自动选择第一个小队。配置少，但空间新增小队后会改变行为或重新询问。
3. 在运行配置中维护显式的“空间 ID → 默认小队 ID”策略，并在每次创建前通过 Multica CLI 实时校验。该方案可审计、可扩展、不会因小队排序或重名误派，采用此方案。

## 数据模型

新增配置 `multicaWorkspaceDefaultSquads`，每项包含：

- `workspaceId`：目标空间不可变 ID；
- `squadId`：默认承接小队不可变 ID；
- `workspaceName`、`squadName`：仅用于可读诊断，不参与身份判断。

北京空间配置为：

- 空间：`北京AI流程管理特训营`（`0a87c021-0a7e-448f-afa2-9cade200ecaf`）
- 小队：`詹老师的搞事小团队`（`a99127ae-906c-4926-a9e4-3e26946ee8f1`）

## 创建链路

1. 沿用现有跨渠道需求收集逻辑，先取得需求内容并解析目标空间。
2. 若空间仍不确定，继续询问用户；无法确定时仍以 `my super work space` 作为显式兜底。
3. 空间确定后，读取该空间的实时小队清单。
4. 若存在空间级默认小队配置，按 `squadId` 精确校验其仍属于当前空间：
   - 校验成功：自动生成小队选择，写入 Issue `assigneeId` 并走现有小队执行链路；
   - 校验失败：停止创建，返回明确配置错误并写审计，绝不降级为无负责人 Issue。
5. 未配置默认小队的空间继续使用现有行为：无小队时仅创建；有小队时询问用户选择。
6. 通过需求补全、直接创建、空间改选等入口进入的请求，都复用同一个默认小队解析函数。

## 存量需求

将本次刚创建的 `BEIJ-4` 更新为由「詹老师的搞事小团队」承接，并保留原始需求内容和空间。

## 审计与错误处理

- 自动采用默认小队时记录空间 ID、小队 ID 和来源渠道。
- 配置存在但实时小队清单不匹配时记录失败事件，并向原会话返回可操作错误。
- 不以名称模糊匹配，不选择第一个小队，不静默回退到仅创建模式。

## 测试与验收

- 单元测试：精确命中、其他空间不命中、配置小队缺失时失败关闭。
- 路由测试：北京空间跳过小队询问并携带正确 `assigneeId`；其他空间保持原行为。
- 回归测试：跨渠道入口、空间询问和 `my super work space` 兜底不受影响。
- 线上验收：CLI 读取配置与实时小队一致；新建测试需求能由目标小队承接；`BEIJ-4` 的负责人更新成功；服务健康检查通过。
