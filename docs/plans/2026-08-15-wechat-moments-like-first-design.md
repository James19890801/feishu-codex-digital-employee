# 微信朋友圈“先点赞、能评论则评论”设计

## 目标

在现有朋友圈互动 worker 上增加点赞能力。基线之后出现的非本人新动态，先点赞；内容能够被可靠理解并可围绕具体细节回应时，再生成自然评论。别人对本人朋友圈或数字人评论的回复仍然优先处理。

## 方案

- 使用 GeWe `POST /gewe/v2/api/sns/likeSns`，`operType=1` 点赞。
- 点赞和评论使用不同的持久化执行键；成功、失败或结果不明确后都不自动重复提交。
- 每日最多点赞 30 条；不对历史基线补点赞，不点赞本人动态。
- 新动态的执行顺序为点赞后评论。评论继续过滤广告、敏感内容、信息不足和需要虚构经历的内容。
- 已见动态、已点赞动态、已评论动态分别持久化；服务重启和分页重叠不会造成重复。
- 写入失败连续两次则当日熔断，审计日志只保存哈希、计数和错误码。

## 验证

- 适配器测试验证接口路径、`operType=1` 和 64 位 `snsId` 精度。
- worker 测试验证新动态先点赞后评论、不可评论动态只点赞、重扫不重复、历史基线零动作。
- 全量测试、真实接口只读检查、服务重启后立即扫描，并通过审计确认本轮动作数量。
