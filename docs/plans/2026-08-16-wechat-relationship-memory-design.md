# 微信人物关系记忆设计

## 目标

让数字人在个人微信私聊、群聊和朋友圈中以同一个 `wxid` 为人物主键，持续理解“对方是谁、双方发生过什么、当前关系如何、哪些事情尚未结束”，并在每次回复前加载经过受众隔离的关系上下文。第一期不自动合并飞书、钉钉身份，只预留人工确认映射接口。

## 设计原则

1. **人物优先，而不是会话优先**：聊天、群聊和朋友圈只是同一人物关系的不同发生场景。
2. **事件不可变，事实可失效**：保留原始事件和来源；新事实关闭旧事实的有效期，不悄悄覆盖历史。
3. **证据优先于推断**：所有长期事实必须有来源事件；明确陈述优先于模型推断，低置信推断不得进入回复。
4. **受众隔离是硬边界**：私聊信息不得进入群聊或朋友圈；群信息不得跨群；公开朋友圈信息可在公开互动中使用。
5. **关系记忆影响语气，不炫耀记忆**：除非当前问题需要，不主动说“我记得你以前……”。
6. **本地优先**：复用现有 SQLite 和本地 AI 运行时，不新增云端记忆服务。

## 现状与缺口

现有 `conversation` 表按 `chat_id` 保存短期历史，单次生成最多注入最近 50 条消息；每日学习会匿名化人物，只能形成全局行为规则。朋友圈互动只向模型提供当前动态、当前评论和本地专业知识。因此同一 `wxid` 在私聊、多个群、朋友圈中的经历没有统一人物视图。

## 架构

### 1. 身份层

统一人物主键为 `wechat:<wxid>`。聊天 webhook 中的 `wechat:<wxid>` 和朋友圈数据中的原始 `wxid` 都归一到该主键。昵称、备注、群昵称和别名只是属性，永远不能作为自动合并依据。

### 2. 情景事件层

`relationship_episode` 保存不可变事件：

- 私聊入站与出站；
- 群聊入站与针对该人物的出站；
- 朋友圈发布、评论、回复和点赞观察；
- 事件时间、发生场景、来源 ID、方向、文本摘要和受众范围。

事件使用来源 ID 做幂等键。原始事件只保存在本机，敏感凭证和密钥不进入关系记忆。

### 3. 语义事实层

`relationship_fact` 保存可复用信息，例如人物资料、偏好、专业兴趣、计划、共同经历和未完事项。每条事实包含：

- 人物主键；
- 类型与规范化内容；
- 置信度；
- `valid_from` / `valid_until`；
- 来源事件；
- 受众范围；
- 当前、失效或删除状态。

模型只负责提出候选事实。写入前必须经过结构校验、敏感内容过滤、来源验证、去重和冲突处理。

### 4. 关系状态层

`relationship_profile` 保存短小、始终可用的关系胶囊：

- 推荐称呼与稳定显示名；
- 熟悉程度；
- 合适的沟通语气；
- 常聊主题；
- 双方共同经历；
- 未完事项；
- 最近互动时间。

关系胶囊是可重建派生数据，不替代事件和事实来源。

### 5. 写入路径

- **热路径**：消息或朋友圈数据到达时，确定人物、场景和受众范围，幂等写入事件，不调用模型，不增加回复延迟。
- **后台反思**：按人物合并尚未处理的事件，异步提取事实、更新有效期和关系胶囊。
- **关键显式事实**：对方明确说出称呼、偏好、计划或待跟进事项时，可以被下一轮后台任务优先处理。

### 6. 召回路径

每次微信回复前执行：

1. 用 `wxid` 定位人物；
2. 根据当前场景建立允许的受众范围；
3. 加载短关系胶囊；
4. 从事实和事件中筛选与当前问题最相关的 3–6 条；
5. 按身份匹配、受众范围、置信度、相关性、重要性和时间排序；
6. 以“可能不完整，不得主动暴露来源”的内部上下文注入模型。

召回上下文与本地专业 Wiki 分开：人物记忆回答“我和谁在说话”，Wiki 回答“专业问题应该怎么答”。

## 受众范围

- `private:<personId>`：只允许该人物私聊。
- `group:<chatroomId>`：只允许原微信群。
- `public_moments`：允许公开朋友圈互动。
- `owner_only`：只允许 Owner 管理界面，不进入对外生成。

关系熟悉程度和沟通风格可以跨场景影响措辞，但任何具体私聊事实都不能进入群聊或朋友圈。

## 朋友圈集成

扫描到朋友圈时，先把作者动态和评论写入事件层。生成评论前按目标 `wxid` 获取 `public_moments` 关系上下文；回复别人对本人朋友圈的评论时，以评论人的 `wxid` 为目标。发送成功后再记录出站事件。模糊或失败的写入结果沿用现有幂等和不自动重放机制。

## 错误与隐私处理

- 不能确认人物主键：只保留当前上下文，不写长期记忆。
- 后台模型输出不合法：丢弃候选，不影响正常回复。
- 事实冲突：保留旧记录并关闭有效期，不能直接覆盖。
- 敏感内容：验证码、密钥、财务、健康、政治、宗教和心理推断默认拒绝长期化。
- 昵称冲突：绝不按名称合并人物。
- 删除与修正：Owner 可按人物删除全部记忆或使单条事实失效；删除操作写审计，不记录被删除正文。

## 上线策略

1. 建表、事件采集和历史回填，回复行为保持不变。
2. 影子召回，只记录召回命中和延迟，不注入回复。
3. 微信私聊启用关系上下文。
4. 朋友圈启用公开关系上下文。
5. 群聊最后启用，并执行跨受众泄露测试。

第一版在完整自动测试通过后直接启用私聊、朋友圈和群聊；若运行时检测到受众边界异常，自动退化为无关系记忆回复。

## 验收标准

- 同一 `wxid` 在私聊、群聊和朋友圈归入同一人物。
- 不同 `wxid` 即使同名也绝不合并。
- 私聊事实进入群聊或朋友圈的泄露数为 0。
- 事件重复写入数为 0。
- 每条事实都能追溯到来源事件。
- 过期事实不会作为当前事实召回。
- 无可靠记忆时自然退化，不虚构关系。
- 召回 P95 小于 150ms，关系上下文控制在约 1200 tokens 内。
