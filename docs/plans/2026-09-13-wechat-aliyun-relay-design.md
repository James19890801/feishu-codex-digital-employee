# 微信边缘中继迁往阿里云香港轻量服务器

## 已确认范围

用户确认只迁移微信固定回调链路，目标是停止日常流量消耗 Cloudflare Worker 免费额度。当前链路为 GeWe → Railway 固定域名 → Cloudflare Worker Durable Object/KV → 本机 HTTPS 轮询。钉钉云端兜底、Cloudflare 许可服务、香港服务器上现有 `aipro` 网站均不在迁移范围。

目标机器是阿里云香港轻量应用服务器，Alibaba Cloud Linux 3、2 vCPU/2 GiB/40 GiB，现有 Nginx 占用 80/443、PM2 网站占用 4000。迁移服务只绑定 `127.0.0.1` 独立端口，经 Nginx 独立虚拟主机 `wxrelay.e2eskill.cn` 暴露 HTTPS，不修改现有网站路由。实例 2026-09-21 到期，用户自行续费；正式切流须验证续费后的到期时间。

## 方案取舍

1. Cloudflare 升级付费：实现成本低，但无法消除平台依赖和配额问题。
2. 现有阿里云服务器独立中继：不增加机器、最小改动现有微信消费者；单机故障需要备份与明确回滚。**采用此方案。**
3. 阿里云负载均衡、RDS、OSS：可扩展性更强，但现阶段成本与运维复杂度过高。

## 数据流与组件

GeWe 将回调 POST 到 `https://wxrelay.e2eskill.cn/webhooks/gewe/<现有回调密钥>`。Nginx 只代理该域名到本机 Node 中继。中继校验 Content-Type、体积和 JSON 后，用 SHA-256 摘要去重，将正文和到达时间以 SQLite WAL 事务持久化；提交成功才向 GeWe 返回 200，失败返回非 2xx，保留上游重试机会。不得打印消息正文、联系人或凭据。

本机 relay agent 沿用 `/relay/lease`、`/relay/ack`、`/relay/status` 协议，租约交付成功后 ACK；租约超时重投，本地现有消息 ID 去重仍生效。附件沿用原上传接口和公开路径，限制 25 MiB、30–900 秒 TTL，文件原子落盘于专用目录并定期清理，不进入网站目录。控制接口由原有高熵 Bearer token 保护；秘密只保存在服务器权限受限的运行环境和 Mac Keychain，不提交仓库。

为防单机资源耗尽，中继限制请求大小、并发与队列上限；超限明确返回非 2xx，不伪报接收。仅状态和计数进入监控。定期备份 SQLite 与运行配置；备份不携带回调密钥、令牌，也不公开消息正文。备份保留策略、磁盘空间告警和实例到期提醒必须在切流前验证。

## 部署、验收与回滚

先实现与现有 Worker 协议一致的服务和自动化测试，再在香港机独立目录、独立用户/进程部署。为新域名配置 DNS 与证书，验证外部 HTTPS、签名 canary、真实附件上传下载。使用不带真实消息的测试回调演练：本机 relay 停止时云端积压增加，恢复后补投、ACK 且不重复回复。并行观察现有网站与中继的 CPU、内存、磁盘和日志。

切流前确认实例已续费、旧队列为零、GeWe 回调登记可查询、Mac 状态健康。切流时先让 Mac relay agent 指向新域名，验证可租约；随后更新 GeWe 回调。切流后核对注册 URL、队列积压、消息收发及附件。旧 Railway/Cloudflare 入口短期保留但无日常流量，仅作可逆回滚；若验收失败，恢复旧 Mac relay origin 与 GeWe 回调，并按消息 ID 对账，不直接清空任何队列。

## 非目标与剩余风险

不迁移历史 Cloudflare 队列正文；切流前须排空并核对。单台香港机仍为单点，且原有 GeWe 接入没有全量历史补拉实现，因此当机房或域名长时间不可用且上游重试耗尽时，无法声称零丢失。此次不主动改动 SSH 安全组或现有网站配置之外的虚拟主机。续费付款、可能的额外流量费用由用户决定。
